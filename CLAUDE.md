# Проект: цифровизация «90 градусов»

Металлообработка, цех 8 человек. Владелец — Дмитрий Шарапов. Работаем по этапам, сейчас — производство, этап 2 «Минимальный учёт».

## Начало каждой сессии
1. Прочитай `docs/00_паспорт_проекта.md` — главный документ (статус, решения, открытые вопросы).
2. Подробности — по необходимости: `docs/01_план_цифрового_производства.md` (план), `03` (калькулятор), `04` (сотрудники), `05` (итоги этапа 1, Anar).
3. `docs/archive/` — устаревшее, читать только по прямой просьбе.

## Правила
- Отвечай по-русски, коротко и по делу. Не пересказывай то, что уже есть в документах.
- Неизвестное помечай явно («НЕ ИЗВЕСТНО», «ДОПУЩЕНИЕ»), ничего не выдумывай.
- Расчёты и цифры — только кодом (Python в `scripts/`), не «на глаз».
- После каждого этапа предлагай обновить паспорт: статус, решения (в «Журнал решений» с датой), открытые вопросы. Решения храни в паспорте, а не в переписке.
- Экономь лимиты: из Битрикса бери только нужный заказ, данные — выгрузками.

## Секреты и данные
- Токены, вебхуки, пароли в чат не принимай и в файлы репозитория не пиши; если присылают — предупреди. Секреты только в `.env` (в `.gitignore`) или в настройках MCP (`claude mcp add ... -s local`).
- Зарплатные суммы не переносить в документы: только имена и роли; допустимы агрегаты (труд по заказу в рублях).
- Клиентские выгрузки и персональные данные — только в `data/` (не попадает в git).
- В git: код, техдокументация, документы проекта. Без клиентских данных.

## Структура
- `docs/` — документы проекта (бывший проект claude.ai «90 Градусов»).
- `scripts/` — расчётные скрипты.
- `data/` — выгрузки (локально, не в git).
- `app/` — будет код производственного модуля (этап 2+).
