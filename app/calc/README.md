## Установка с нуля (делает владелец файла или редактор)
Ставить от того аккаунта, от имени которого бот будет работать (триггеры работают от установившего). Файл принадлежит daktobegoznal@ — лучше ставить от него.

1. **Копия на всякий случай.** Drive → «Просчет 90гр» → Файл → Создать копию.
2. **Бот.** В Telegram @BotFather → `/newbot` → имя «90 Расчёты». Затем `/setprivacy` → выбрать бота → **Disable** (иначе бот не видит обычные сообщения в группах). Токен никому не пересылать.
3. **Бот в чаты.** Добавить бота в «Расчеты» и «Админ». Если бот был добавлен до шага `/setprivacy` — удалить и добавить снова.
4. **Код.** В таблице: Расширения → Apps Script. Создать файлы `Code.gs` и `Logic.gs`, вставить содержимое из репозитория. Настройки проекта (шестерёнка) → включить «Показывать файл манифеста appsscript.json» → вставить `appsscript.json`.
5. **Токен.** Настройки проекта → Свойства скрипта → добавить `TG_TOKEN` = токен бота.
6. **Б24 (желательно сразу).** Б24 → Разработчикам → Другое → Входящий вебхук → права **CRM** → сохранить. Лучше от отдельного технического пользователя с доступом только к сделкам. Ссылку вида `https://90gradusov.bitrix24.ru/rest/…/…/` — в свойство `B24_WEBHOOK`. Без него лист называется только по ID, без клиента.
7. **Запуск.** Обновить таблицу → меню «90°» → «Установить / обновить автоматизацию» → разрешить доступ. Появятся листы `шаблон_v2`, «Цены», «Реестр», «Журнал_правок», «Счета_входящие», «Настройки».
8. **Настройки.** Лист «Настройки»: `tg_manager` — логин Екатерины, `tg_raschetchik` — логин Андреева (без @).

## Как пользоваться
- **Екатерина:** `#1234 ТЗ…` в «Расчеты». Повторное `#1234 …`, пока расчёт не утверждён, дописывает ТЗ в тот же лист. После утверждения — создаёт `…_v2`.
- **Андреев:** заполняет лист как раньше. Новое: строки «Доп. работы / доп. стоимость, ₽» и «Что входит» — подряд, покупное, разовые работы по изделию, без коэффициента. Готово — статус «Заполнено».
- **Екатерина:** проверяет. Правки после «Заполнено» пишутся в «Журнал_правок». Не так — текст в «Комментарий проверки» и статус «На доработку». Всё ок — «Утверждено»: цены фиксируются, лист закрывается от правок.
- **Цены:** правятся только в листе «Цены» (цена, дата, источник). Новый расчёт берёт их оттуда, утверждённые не меняются. Новый материал — добавить строку в «Цены» и в `шаблон_v2` (в нужный раздел, формула в B как у соседей, ключ «раздел | материал»).

## Цены из счетов (этап 3, установлен 16.10.2026)
Как работает:
1. Кто-то кладёт счёт в чат «Админ» (PDF, Excel или фото). Бот пишет строку в «Счета_входящие» (как и раньше).
2. Раз в 10 минут `processInvoices`: скачивает файл из Telegram в папку Drive «Счета из чата Админ» (рядом с таблицей), распознаёт штатным OCR Google (копия — в подпапке «распознано»), находит № счёта, дату, поставщика и строки «позиция — кол-во — ед. — цена — сумма».
3. Доставка, резка, услуги, итоги и НДС пропускаются. Остальные позиции попадают в лист **«Цены_предложения»**: материал справочника подобран автоматически, цена пересчитана в единицу калькулятора:
   - ₽/т или ₽/кг → ₽/м² листа: по толщине и плотности (сталь 7850, нерж 430 — 7700, другая нерж — 7900 кг/м³);
   - ₽/т → ₽/м трубы: масса метра по размеру и стенке из счёта (профильная — ГОСТ 30245, круглая — по стенке, пруток — сплошной);
   - ₽/лист → ₽/м² — по размеру листа; ₽/шт трубы → ₽/м — по длине (`L=6000`);
   - не хватает данных (нет стенки, размера листа) — цена пустая, в «Как пересчитано» написано, чего нет.
4. **Подтверждение — только человеком, в самой таблице.** В строке предложения: проверить материал (выпадающий список, можно сменить — цена пересчитается), при необходимости исправить «Новая цена» (жёлтая колонка), в «Решение» (синяя колонка) выбрать «Принять» или «Отклонить».
   - «Принять» → цена, дата счёта и источник («поставщик, счёт № … от …») записываются в «Цены»; запись в «Цены_история» (было/стало, кто).
   - Не принимается, если не выбран материал, нет цены или в «Цены» уже стоит цена от более свежего счёта.
   - Изменение больше ±30% подсвечивается красным — проверить, нет ли ошибки.
   - Решение повторно не меняется; ручная правка «Цены» тоже пишется в «Цены_история».
5. Новые и неутверждённые расчёты сразу считают по новой цене (формулы `шаблон_v2` → «Цены»). Утверждённые не меняются — цены в них заморожены.

Установка (владелец):
1. В редакторе Apps Script заменить код `Код.gs` (Logic.gs + пустая строка + Code.gs) и `appsscript.json` (добавлена служба Drive API v3).
2. Запустить `setup` → разрешить новые доступы (Drive, Документы). Появятся «Цены_предложения», «Цены_история», колонки в «Счета_входящие», триггер `processInvoices`.
3. «Настройки» → `tg_prices`: кто подтверждает цены (логин или ID из `tg_started`; человек должен написать боту `/start`). Пусто — без оповещений.
4. Проверка: положить счёт в «Админ», через ~10 минут (или запустить `processInvoices` вручную) — строки в «Цены_предложения».
5. Старые счета: экспорт чата «Админ» из Telegram Desktop → загрузить папку на Drive → её ID в `invoices_import` → запустить `importInvoiceFolder`.

## Ограничения
- Задержка реакции бота — до 1 минуты (опрос раз в минуту).
- «Кто правил» в журнале виден только для аккаунтов того же домена Google; для обычных gmail — пусто. Полная история — Файл → История версий.
- Бот видит сообщения только с момента добавления в чат; старые счета из «Админ» — экспортом чата (`importInvoiceFolder`).
- Старые ~90 листов не трогаются; работают как раньше.
- Проверено локально только чистые функции; работа в Google (шаблон, триггеры, бот) — НЕ ПРОВЕРЕНО до установки.
