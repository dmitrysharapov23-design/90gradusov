# 1С → счёт из бота КП

Решения владельца 21.10 и 27.10.2026 (паспорт): бот создаёт и проводит «Заказ клиента» ООО «90 ГРАДУСОВ» в новой базе EtlonKA26 через OData. Счёт PDF рисует бот (`app/invoice/make_invoice.py`, формат печатной формы 1С, снят с ЦБ-138) и ставит подпись и печать (`app/invoice_stamp`).

## Как работает
1. Кнопка «Выставить счёт» в карточке заказа (или слово «счёт»). Нужны реквизиты заказчика (ИНН) и собранное КП или договор; сумма — договор, иначе КП, на весь заказ (ДОПУЩЕНИЕ, как ЦБ-138).
2. Клиент ищется в 1С по ИНН (физлицо — по наименованию), договор — с организацией 90 ГРАДУСОВ, «Договор 90 …». Нет клиента или договора — бот просит завести их вручную (инструкция 16, шаг 1). Создание клиентов и договоров ботом решением разрешено, но пока НЕ сделано.
3. Заказ — копия последнего проведённого заказа 90 ГРАДУСОВ (склад, соглашение, вид операции, номенклатура «Изготовление конструкции из металла»), клиент/договор/сумма/дата свои; поля клиента шаблона (контактное лицо, банковский счёт, адрес) очищаются. Затем проведение.
4. Номер в счёте: «ГРЦБ-000138» → «ЦБ-138» (ДОПУЩЕНИЕ по паре из старой базы). Поле «Код» в образце платёжки пустое: как 1С его считает — НЕ ИЗВЕСТНО.
5. Повторное нажатие — тот же счёт; сумма изменилась — бот спрашивает, выставить ли новый (старый заказ отменять в 1С вручную: изменение и удаление ботом запрещены).

## Подключение (сделано 27.10.2026)
- Учётка — Екатерины (решение 27.10.2026). Если OData ей не разрешён (probe даст 401/403) — администратору 1С добавить её роли право на стандартный интерфейс OData и включить в состав OData организации, контрагентов, партнёров, договоры, номенклатуру, заказы клиентов.
- В `.env`: `ONEC_USER`, `ONEC_PASSWORD` (необязательно `ONEC_TEMPLATE_ORDER` — номер заказа-шаблона).
- Проверка без записи в 1С:
```bash
.venv/bin/python -m app.onec.odata probe
.venv/bin/python -m app.onec.odata draft 2635243000 1000
```
