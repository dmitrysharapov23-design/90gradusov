Что из этого берём в этап 2 (требования к учёту):
- Время фиксировать по операции и позиции, а не по должности.
- Позиция заказа — единица учёта; состав позиций один и тот же в расчёте, договоре и цеху.
- Проблемы с причиной: брак поставщика/подрядчика, ошибка чертежа (с автором версии, включая внештатных), ошибка производства, ожидание согласования.
- Приёмка поставок подрядчика с отметкой качества; затраты на подрядчиков и покупное привязываются к позиции.
- Для крупных позиций в расчёте — план часов по операциям (сварка, гибка, слесарка), чтобы было с чем сравнивать.

## Направление: контроль коммуникаций менеджера (начато 14.10.2026)
Цели владельца:
1. Убрать человеческий фактор: ничего не упустить, ошибки ловятся автоматически.
2. Менеджеру не хватает времени вести карточки — их должен заполнять ИИ, менеджер подтверждает.
3. Саммари по каждому клиенту: история и фактические договорённости.
4. Оценка хода диалога: правильность решений менеджера.
Разбирает сигналы владелец; позже такая же функция нужна РОПу.

Механика:
- Все контакты с клиентами только через каналы компании: звонки с корпоративного номера (ВАТС МТС + FMC), переписка через Wazzup (подключён и активен только Telegram на +7 989 340-90-90; WhatsApp и Max не подключены — проверено в кабинете Wazzup 16.10.2026), почта (подключена к Б24; КП уходят и по почте, и в мессенджерах). Менеджер с личных аккаунтов не пишет. Правило владелец готов ввести.
- По каждому диалогу за день: саммари (о чём, договорённости по цене/составу/сроку/оплате, обещания с датами, открытые вопросы, изменения ТЗ, риски) → комментарий в сделку + сводная карточка «История и договорённости» клиента.
- Сверка → несостыковки → задача владельцу: цена/срок/состав в диалоге ≠ КП/договор/сделка; обещала и не сделала; клиент без ответа > N часов; уступка/скидка без согласования; цена названа, а лид не обработан/сделки нет; изменение ТЗ не дошло до проектировщика.
- ИИ предлагает заполнение карточки (статус лида, сделка, сумма, следующий шаг); менеджер подтверждает. Требует права записи в Б24 (сейчас только чтение) — решение за владельцем.
- Оценка диалога — по эталону (скорость ответа, какие данные собрать до расчёта, когда КП, допустимые скидки, когда звонок/встреча). Предложено: Claude выводит черновик эталона из успешных и проваленных сделок, владелец правит.
- Реализация: Битрикс — витрина (таймлайн, комментарии, задачи). Анализ — модуль того же сервиса: забор звонков/записей и переписки → распознавание речи → саммари и сверка через API ИИ → запись в сделку и задачи. Здесь API нейросети нужен. Стоимость не оценена.
