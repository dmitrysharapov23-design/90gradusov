# Агент по работе с клиентами: автоответ и сбор ТЗ

Черновик 16.10.2026. Механика утверждена владельцем 16.10.2026. Код режима «тень» — `app/client_agent/` (16.10.2026), ждёт ключей; боевой режим не написан. Связанные документы: 06 (эталон, пункты ТЗ), 08 (просчёты), 12 (входящие заявки, приветствие).

## Схема
1. Новый клиент пишет в Telegram (Wazzup → лид в Б24).
2. **Рабочее время** (пн–пт 10–19): агент ждёт ответа Екатерины 2 рабочих часа. Ответила — агент в этот диалог больше не вступает.
3. **Нерабочее время, выходные**: агент отвечает сразу (в пределах интервала проверки) и начинает сбор ТЗ.
4. Нет ответа 2 рабочих часа — автоответ и сбор ТЗ.
5. ТЗ собрано или сработало условие передачи — комментарий «ТЗ (собрал ассистент)» в лид, задача Екатерине «Проверить ТЗ».
6. Екатерина проверяет ТЗ, при необходимости уточняет у клиента, сама отправляет `#ID` в «Расчеты» (08). Дальше КП, договор, счёт 70% и сопровождение — Екатерина.

Заявки из Instagram и с сайта, где первыми пишем мы, — по 12: приветствие с запросом ТЗ сразу, в нерабочее время в 10:00; дальше сбор ТЗ тем же агентом. Стык сделан 16.10 (12, «Стык с агентом клиентов»): приветствие скрипта заявок агент узнаёт по реестру `data/client_agent/external_sent.json`, не принимает за Екатерину, считает в лимит 4 сообщений и ведёт такой лид сразу, без ожидания 2 часов. Если ответ клиента придёт в новый лид Wazzup — связывает его с нашим по Telegram ID / нику / телефону (НЕ ПРОВЕРЕНО, куда Wazzup кладёт ответ). Автоотправка приветствий пока выключена.

## Кому агент пишет
- Только новым клиентам: лид из Wazzup в статусе «Не обработан» (или лид «Инстаграм»/«Веб-сайт», которому скрипт заявок отправил приветствие), нет сделки, Екатерина в чате ещё не писала, нет обращений с того же Telegram ID / телефона за 60 дней (решение 16.10).
- Клиентам с открытой сделкой или заказом в работе агент не пишет. Ответ > 2 часов по ним ловит ежедневная сводка.
- Лиды «не клиент» (поставщики, партнёры, свои) — после фильтра из 12 и паспорта; до фильтра агент может ошибочно написать поставщику. ДОПУЩЕНИЕ: такой риск принимаем на пилоте.

## Как говорит агент
- Представляется: «Ассистент компании «90 градусов»». Не выдаёт себя за Екатерину. Пишет с того же рабочего Telegram через Wazzup.
- Вопросы по эталону 06, пункты 1–6: размеры / чертёж / фото-референс; количество; материал и цвет; город, доставка, монтаж; срок; для кого заказ (для себя, компания с НДС, дизайнер). Бюджет — только для проектных запросов.
- 1–2 вопроса за сообщение, только то, чего ещё нет. Фото и файлы принимает и отмечает в ТЗ.
- Никогда: цены, сроки изготовления, скидки, обещания, споры, советы по конструкции.

Первый автоответ (на согласование):
> Здравствуйте! Я ассистент компании «90 градусов». Екатерина сейчас занята{ / Сейчас нерабочее время}, она ответит вам {в ближайшее время / завтра с 10:00}. Чтобы ускорить расчёт, задам несколько вопросов.
> {первые 1–2 вопроса}

Передача Екатерине (сообщение клиенту):
> Спасибо, всё записал и передал Екатерине. Она проверит и вернётся к вам с расчётом.

## Когда агент останавливается и передаёт Екатерине
- Собраны пункты 1–6 (или клиент ответил, что чего-то нет).
- Клиент спрашивает цену, срок, скидку, просит звонок или встречу.
- Жалоба, раздражение, «вы бот?», вопрос не по заказу, непонятное сообщение.
- 4 сообщения агента без полного ТЗ или клиент молчит 24 часа — передаёт то, что есть.
- Екатерина написала в чат — агент молча выходит из диалога навсегда.

## Где и как работает (Mac владельца)
- Скрипт `app/client_agent/` по launchd каждые 2 минуты. Условия как у сводки (решение 15.10): Mac включён и не спит, приложение Claude не нужно — агент вызывает API Claude напрямую.
- Входящие читает из таймлайна лидов Б24 (Wazzup пишет туда сообщения). Новые сообщения не меняют дату изменения лида — поэтому опрашиваются все лиды «Не обработан» пачками (batch). НЕ ПРОВЕРЕНО, укладывается ли это в лимиты Б24; альтернатива — вебхук Wazzup на входящие (нужен внешний адрес, на Mac — через туннель).
- Отправка — API Wazzup (канал Telegram +7 989 340-90-90). НЕ ПРОВЕРЕНО, что сообщение через API уходит от рабочего аккаунта и видно Екатерине в чате.
- Запись в Б24 — отдельный входящий вебхук: комментарий в лид, поля лида, задача Екатерине. Ничего не удаляет, лиды не конвертирует.
- Журнал действий агента — `data/client_agent/` (не в git).
- Сторож: если агент не работал > 15 минут в рабочее время — предупреждение владельцу в Telegram (как `check_summary.sh`).
- Риск Mac: выключен/спит/нет интернета — клиенты не получают ответа. Сервер — когда агент себя оправдает.

## Разрешения (решение владельца 16.10.2026)
1. Агент отправляет сообщения клиентам автоматически, без подтверждения каждого, строго в рамках этого документа.
2. Агент пишет в Б24 через отдельный вебхук: комментарий, поля лида, задача Екатерине. Ограничения MCP (`crm_update`, `crm_comment_add` с подтверждением) для Claude в чате не меняются.
3. Ключи — в `.env`, кладёт владелец сам (в чат не присылать):
   - `B24_AGENT_WEBHOOK` — Б24 → Разработчикам → Другое → Входящий вебхук; права: CRM, Задачи. Лучше от технического пользователя.
   - `WAZZUP_API_KEY` — кабинет Wazzup → Интеграции → API.
   - `ANTHROPIC_API_KEY` — console.anthropic.com (отдельный от подписки Claude платёжный аккаунт; стоимость НЕ ИЗВЕСТНО, оценить после пилота).
   - Telegram-бот для предупреждений — уже есть (сводка).

## Порядок запуска
1. Владелец: ключи в `.env`, утвердить тексты выше.
2. Проверка API Wazzup: отправить одно сообщение на свой второй аккаунт.
3. Режим «тень» 3–5 рабочих дней: агент читает, решает и пишет черновики ответов в `data/client_agent/`, клиентам не отправляет. Владелец смотрит, что агент сказал бы.
4. Включение отправки. Первая неделя — каждую передачу ТЗ смотрит владелец.
